# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## プロジェクト概要

書籍『安心、楽しい、大丈夫。』とその自己肯定感ワークシートをもとにした、個人用の自己肯定感トラッカー。
成果物は `自己肯定感ノート.html` の 1 ファイルのみ。同ディレクトリの PDF（`安心安全大丈夫.pdf`、`自己好転換ワークシート .pdf`）は文言・6分類・各ワークの出典資料であり、コードからは参照していない（後者はテキストレイヤーのないスキャン PDF なので、読むには PyMuPDF でページを画像化する）。

ワークシートのうち **毎日つづけられるもの**だけを実装している。ライフチャート、バケットリスト、タイムライン、イメトレ文章完成ノート、解決ノート、課題の分離ノート、タイムマネジメントは、日々の習慣にならない単発ワークとして意図的に入れていない。

## ビルド・実行・テスト

ビルドシステム、パッケージマネージャ、テストランナーは存在しない。git リポジトリでもない。

- 実行: `自己肯定感ノート.html` をブラウザで直接開く（`file://` で完全に動作する）
- 動作確認: ブラウザで開いて手動で確認する。状態をリセットするには DevTools コンソールで該当の localStorage キーを削除する（下記）

## アーキテクチャ

単一の自己完結 HTML。外部リソース（CDN、フォント、画像、fetch）を一切読まないため、**依存を追加しないこと**。ビルド工程がないので、JS はトランスパイル不要な ES5 スタイル（`var`、`function`、`IIFE`）で統一されている。既存コードに合わせること。

### ページの構成

上から、今日のことば（唱和カウンタ）／今日のふりかえり／今日の問いかけ／6つの自己肯定感／わたしの言葉／心がざわついた日に／できなかった日に／書いたものを取り出す。
**毎日ひらく順に並べてある**（記録 → 問い → 読み物 → 必要なときの道具）ので、セクションを増やすときはこの流れを崩さないこと。最後の「書いたものを取り出す」は毎日ひらくものではない道具なので、この流れの外側（出典の直前）に置いてある。

### データの持ち方

表示内容は `<script>` 冒頭の 3 つの定数から生成し、DOM は `document.createElement` で組み立てる（静的 HTML があるのは「心がざわついた日に」の 3 つの道具カードだけ。中身が入力フォームで、JS 生成にすると読みにくいため）。

- `CARDS` — 6つの自己肯定感（自己受容感／自己効力感／自尊感情／自己有用感／自己決定感／自己信頼感）。各要素が `cat`・`phrase`・`desc`・`say` を持ち、「6つの自己肯定感」カード群と「今日のことば」抽選プールの両方の元になる
- `QUESTIONS` — ワークシート「自己肯定感が高まる魔法の質問」の 8 問。日替わりで 1 問出す
- `DEFAULT_MINE` — 「わたしの言葉」の初期値。localStorage が未設定のときだけ使われる

### localStorage キー（`LS` オブジェクトに集約）

| キー | 内容 |
| --- | --- |
| `jkk_mine` | 「わたしの言葉」の配列（JSON） |
| `jkk_last` | 最後に3回唱え終えた日の通し日数 |
| `jkk_streak` | 連続日数 |
| `jkk_count` | `"YYYY-M-D:回数"` 形式の当日の唱えた回数 |
| `jkk_diary` | 今日のふりかえり `{d,label,good,why,nice}` の配列 |
| `jkk_qa` | 問いかけの答え `{d,label,q,a}` の配列 |
| `jkk_scale` | エモーショナル・スケーリング `{d,label,name,score,hold,step}` の配列 |
| `jkk_ifthen` | イフゼンのお守り `{d,label,i,t}` の配列 |
| `jkk_shift` | 立場の入れかえ `{d,label,text}` の配列 |
| `jkk_name` | 三人称セルフトーク用に覚えたユーザーの名前（文字列） |

読み書きは `get`/`set`（文字列）と `loadList`/`saveList`（JSON 配列）経由で行う。`file://` やプライベートモードでの localStorage 例外を握りつぶす作りになっているため、`localStorage` を直接触らないこと。

配列系のレコードは必ず `d`（`todayKey()`）と `label`（`stamp()` の表示用日本語日付）の両方を持たせる。`d` は当日分の同定に、`label` は表示にだけ使う。

### 日付まわりの2つの単位

日付処理は目的別に 2 つの関数に分かれており、混同しないこと。

- `todayKey()` — `"YYYY-M-D"` の文字列。当日の唱えた回数（`jkk_count`）の有効判定にのみ使う
- `dayNumber()` — ローカル日付を UTC 基準の通し日数に直した整数。**日替わりの抽選**（`pool[dayNumber() % pool.length]`）と**連続日数の判定**（前日 = `dayNumber() - 1`）に使う

「今日のことば」の抽選プールは `CARDS` + `mine` の連結なので、ユーザーが言葉を追加するとプール長が変わり、その日の表示も変わりうる。「今日の問いかけ」も `dayNumber() % 8` で日替わりに切り替わる。

### アコーディオンの高さ

`.card-body` は `max-height` の遷移で開閉するため、開いたまま中身が増えると下が切れる。記録を追加する処理のあとは必ず `refreshOpen()` を呼んで測り直すこと。道具カードの中には `<details class="why">` が入れ子になっており、こちらは `bindWhy()` が `toggle` イベントで同じ関数を呼んで追従させている。スマホの画面回転やソフトキーボードでも折り返し行数が変わるので、`resize` / `orientationchange` からも呼んでいる。**カード内に高さの変わる要素を足すときは、この経路を通しているか確認すること。**

### 書き出し（`bindExport()`）

「書いたものを取り出す」は 2 種類を出し分ける。`buildText()` が人が読むためのプレーンテキスト、`buildJson()` が `LS` の全キーを生値のまま入れた控え（`{app,version,exportedAt,data}`）。どちらも同じプレビュー欄に出したうえで、コピー／`Blob` + `<a download>` での保存／`navigator.share`（ファイル共有が使える端末のみボタンを出す）に渡す。**外部への送信はしないので、`file://` で完結する原則は崩れていない。**

読み戻し（インポート）は実装していない。JSON の控えは、必要になったら `localStorage.setItem()` で戻す前提の生データ。

### スマホ表示

`@media (max-width:600px)` が余白・カード内の詰めを、`@media (pointer:coarse)` が指で触る端末の共通事項（横向きも含む）を受け持つ。守るべき点が 2 つある。

- **入力欄のフォントサイズは 16px 未満にしないこと。** iOS Safari は 16px 未満の入力欄にフォーカスすると画面を勝手に拡大し、戻らない。`rem` 指定だとユーザーの文字サイズ設定しだいで下回るので、ここだけ `px` で固定してある（`#exBox` は ID 指定に負けるため個別に上書き）
- 穴うめ文（`.fill`）はスマホでは `input.inline` を `display:block; width:100%` にして縦に並べる。同時に `.fill .nw` の `white-space:nowrap` を解除している（横あふれの原因になるうえ、入力欄が独立するので折り返し防止が不要になるため）

### 「なぜ、これが効くのか」の解説（`.why`）

各ワークには研究の裏づけを書いた折りたたみ解説がついている。初期状態は閉じで、読みたい人だけが開く。内容は Web で確認した実際の研究に基づく。**数字（66日、18〜254日、d = .65、6か月後など）や結論を、確認せずに書き換えたり盛ったりしないこと。** 出典リンクはページ末尾の「このノートが下敷きにしたもの」にもまとめてある。

外部リンクは張るが、外部リソースの**読み込み**はしない。この区別を守るかぎり `file://` で完結する原則は崩れない。

### 仕様上の意図的な制約

- **書いたものは消せない**。「わたしの言葉」も各記録も削除 UI を持たない。ユーザーの明示的な要望による仕様なので、削除機能を足さないこと（消したい場合は該当キーを `localStorage.removeItem()`）
- 当日分だけは上書きできる。`jkk_diary` / `jkk_qa` は `d === todayKey()` のレコードを探して差し替える作りで、日付が変われば新しい行として積まれる
- 「今日のことば」は 1 日 3 回まで。3 回目で `markDone()` が走り連続日数が加算される
- 連続日数が途切れても記録は消さず、「これまで N 日・今日からまた1日目」と表示する
- ふりかえりの進捗マスは 21 個（ワークシートの「3週間続けましょう」に対応）。21 日を超えると 2 周目として数え直し、累計日数は別に出す
- ただし **21 日という数字自体に根拠はない**（実測の中央値は 66 日）。マスは目安であって課題ではないので、連続を切らしたことを咎める文言や、途切れたらリセットする挙動を入れないこと。1 日抜けても習慣化は妨げられないことが分かっている
- ふりかえりの「どうして、それが起きたんだろう？」は飾りではなく **Three Good Things の効き目の中心**。省略や統合をしないこと
- エモーショナル・スケーリングには 2 つの問いがある。**「なぜ 10 点ではないのか」（すでに支えているものを見つける）**と「1 点だけ下げるには」。0 点を目指す方向に文言を動かさないこと
- 「わたしの言葉」の解説にあるとおり、**受け入れられる範囲の外にある断定的な励ましは逆効果になりうる**。アファメーションを増やす方向の変更をするときは、この注意書きも一緒に保つこと
- 書き出しは記録を**外に出すだけ**で、消したり書き換えたりしない。読み戻しを足すなら、既存の記録を上書きしない形（追記・併合）にすること
